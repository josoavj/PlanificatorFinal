Installer Planificator

Planificator est une application de bureau qui se connecte à une base MySQL administrée par vous ou votre organisation.

Dans ce guide
  • Prérequis
  • Préparer MySQL
  • Installer l’application
  • Configurer la connexion

Prérequis

  • Un poste Windows, Linux ou macOS pour exécuter l’application de bureau.
  • Un serveur MySQL 8 ou une version MariaDB compatible, local ou accessible sur le réseau privé.
  • Les droits nécessaires pour créer une base et les tables du schéma lors de l’initialisation.

Préparer la base MySQL

Le script fourni se trouve dans scripts/Planificator.sql. Il supprime puis recrée la base Planificator : ne l’exécutez pas sur une base contenant des données à conserver.

Attention : l’import est destructif. Pour une installation existante, effectuez une sauvegarde vérifiée et planifiez une migration adaptée au lieu de réimporter le schéma initial.
mysql -u root -p < scripts/Planificator.sql

Pour un serveur partagé, créez un compte MySQL réservé à l’application et limitez son accès aux postes autorisés. Configurez TLS si les connexions traversent un réseau non fiable.

Installer l’application

Utilisez le paquet de distribution fourni par votre organisation. Les workflows du dépôt produisent des archives et installateurs Windows, ainsi qu’une archive et un paquet Debian pour Linux. Le dépôt contient également les projets Flutter desktop pour macOS ; la disponibilité d’un installateur dépend de la distribution publiée.

Après installation, ouvrez Planificator. Si la base n’a pas encore été configurée, l’écran de configuration vous demande l’hôte, le port, le nom de base et les identifiants MySQL.

Configurer la connexion

  1. Pour MySQL local, utilisez l’hôte de la machine qui héberge MySQL ; pour une base partagée, utilisez son nom DNS ou son adresse IP privée.
  2. Vérifiez le port MySQL (généralement 3306), le nom de base Planificator, puis le compte dédié.
  3. Testez la connexion depuis Planificator et enregistrez la configuration.
  4. Sur une base vide, créez le premier compte administrateur. Son code de récupération est affiché une seule fois : conservez-le hors de l’application.

Au démarrage, les migrations versionnées peuvent créer ou modifier des tables, index et triggers. Le compte MySQL configuré doit disposer des droits DDL nécessaires à ces migrations, en plus des droits de lecture/écriture. Les identifiants sensibles sont enregistrés dans le stockage sécurisé du système d’exploitation ; l’hôte, le port et le nom de base ne sont pas des secrets.

Après l’installation
