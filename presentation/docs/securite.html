Sécurité et protection des données

Planificator est une application desktop qui se connecte directement à la base MySQL choisie par l’organisation. La sécurité dépend donc à la fois du poste, de l’application, du serveur et du réseau.

Mesures intégrées

  • Mots de passe de compte : hachés avec BCrypt ; ils ne sont pas enregistrés en clair.
  • Identifiants MySQL : nom d’utilisateur et mot de passe enregistrés via le stockage sécurisé du système. L’hôte, le port et le nom de base sont des paramètres de connexion.
  • Requêtes : les opérations des repositories utilisent des paramètres SQL pour les valeurs métier.
  • Transactions : les opérations multi-étapes importantes sont regroupées en transactions lorsque nécessaire.
  • Tentatives de connexion : cinq échecs dans une fenêtre de dix minutes déclenchent un blocage temporaire de quinze minutes sur le poste.
  • Récupération : le code initial de récupération admin est stocké sous forme de hash et invalidé après réinitialisation du mot de passe.
  • Journaux : les valeurs sensibles sont filtrées avant l’écriture des logs applicatifs.

Architecture réseau

Il n’y a pas d’API intermédiaire dans l’architecture actuelle : chaque poste Planificator établit une connexion MySQL avec le serveur configuré. La base est ainsi partagée sur le réseau local, mais le serveur MySQL doit accepter les connexions de chaque poste autorisé.

Conséquence : une personne qui récupère un compte SQL doté de droits étendus peut agir directement sur la base et contourner les contrôles d’interface de l’application. Les validations côté Flutter et les triggers ne remplacent pas une séparation de privilèges serveur.

Recommandations pour un réseau local

  1. Créez un compte SQL dédié à l’application, avec uniquement les droits nécessaires sur la base Planificator. L’application exécute des migrations DDL au démarrage : incluez les droits requis pour ces opérations dans votre modèle d’exploitation.
  2. Restreignez le port MySQL aux adresses IP des postes Planificator et au sous-réseau privé prévu.
  3. Interdisez l’exposition du port 3306 à Internet. Activez TLS si le trafic peut traverser des segments non fiables.
  4. Protégez l’accès administrateur au serveur et séparez les identifiants d’administration des identifiants utilisés par l’application.
  5. Chiffrez les sauvegardes, limitez leurs accès et testez périodiquement leur restauration.
  6. Maintenez le système d’exploitation, MySQL et les dépendances à jour.

Incident ou perte d’accès

En cas d’accès suspect, désactivez le compte SQL concerné, changez ses secrets depuis un poste de confiance, vérifiez les journaux MySQL et restaurez les données depuis une sauvegarde connue si nécessaire. Pour un mot de passe admin oublié, utilisez le code de récupération conservé lors du bootstrap.

Cette page décrit l’architecture et les contrôles présents dans le projet ; elle ne constitue ni une certification ni un audit de sécurité indépendant.
