Contribuer au projet

Les contributions doivent préserver la cohérence métier, les données MySQL et l’expérience desktop.

Préparer son environnement

  • Installer Flutter et Dart conformément à pubspec.yaml.
  • Récupérer les dépendances avec flutter pub get.
  • Utiliser une base MySQL de développement isolée de toute donnée réelle.
  • Lire le guide d’architecture avant d’ajouter de nouvelles opérations de données.

Conventions d’architecture

  • Placez les règles métier et l’accès aux données dans les repositories ; évitez les requêtes SQL dans les widgets.
  • Centralisez les requêtes réutilisées dans lib/core/sql_queries.dart.
  • Utilisez des paramètres SQL pour toute valeur fournie par l’utilisateur.
  • Encapsulez les écritures dépendantes dans une transaction.
  • Réutilisez les validateurs et formateurs partagés pour les montants, téléphones et identifiants NIF/STAT.
  • Ne placez aucun mot de passe, jeton ou donnée réelle dans le dépôt ou les logs.

Avant de soumettre un changement

  1. Ajoutez ou mettez à jour des tests pour les règles métier touchées.
  2. Exécutez dart format sur les fichiers modifiés.
  3. Exécutez flutter analyze puis flutter test.
  4. Vérifiez le parcours desktop concerné et les cas d’erreur réseau ou SQL.
  5. Mettez à jour les guides HTML et l’historique des évolutions si le comportement visible change.

Schéma SQL et sécurité

Le script initial scripts/Planificator.sql est destructif. Si une modification de schéma est nécessaire, fournissez également une migration compatible avec les bases existantes. Ne supposez pas qu’une validation côté interface protège les données contre un accès SQL direct.
