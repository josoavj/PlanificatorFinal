Maintenance technique et développement

Ce guide s’adresse aux personnes chargées de maintenir le code, préparer une compilation ou diagnostiquer un changement. L’installation normale ne nécessite pas de récupérer ni de compiler les sources.

Réservé à la maintenance : les commandes ci-dessous sont destinées à un poste de développement. Utilisez une base MySQL de test ; le script SQL initial supprime puis recrée la base Planificator.

Prérequis techniques

  • Flutter stable avec une version de Dart compatible avec la contrainte ^3.10.4 de pubspec.yaml.
  • Git et un accès réseau pour récupérer le dépôt et les dépendances Dart.
  • MySQL 8 ou MariaDB compatible pour tester les fonctions connectées.
  • Les outils desktop propres à la plateforme cible : Visual Studio pour Windows, GTK et les outils de compilation pour Linux, Xcode pour macOS.

Les versions de Flutter et les outils de packaging peuvent évoluer ; le workflow de livraison du dépôt indique les outils utilisés pour les artefacts publiés.

Récupérer les sources

Depuis un terminal, clonez le dépôt puis placez-vous à sa racine :

git clone https://github.com/josoavj/PlanificatorFinal.git
cd PlanificatorFinal
flutter pub get

La racine doit contenir pubspec.yaml, lib/, test/ et scripts/.

Préparer une base de test

Configurez un serveur MySQL isolé du serveur de production et utilisez un compte de développement séparé. Le script scripts/Planificator.sql contient DROP DATABASE IF EXISTS Planificator : il efface la base existante du même nom avant de la recréer.

mysql -u root -p < scripts/Planificator.sql

Au premier lancement, Planificator demande les paramètres MySQL. L’initialisation applique également les migrations versionnées. Le compte de test doit avoir les droits de lecture/écriture et les droits DDL nécessaires aux migrations.

Vérifier le code

Avant de partager un changement, formatez les fichiers concernés, lancez l’analyse statique et la suite de tests :

dart format lib test
flutter analyze
flutter test

Les tests automatisés utilisent des mocks pour les accès SQL. Ils ne remplacent pas une validation manuelle des parcours avec une base de test réelle.

Lancer l’application

Activez le support desktop correspondant puis lancez la plateforme souhaitée :

flutter config --enable-windows-desktop
flutter run -d windows

flutter config --enable-linux-desktop
flutter run -d linux

flutter config --enable-macos-desktop
flutter run -d macos

Exécutez seulement le bloc correspondant au système disponible. La configuration MySQL doit être accessible depuis le poste.

Compiler une version desktop

flutter build windows --release
flutter build linux --release
flutter build macos --release

Les livraisons préparées dans le dépôt produisent des artefacts Windows et Linux. La compilation macOS requiert Xcode et une configuration adaptée à la distribution ciblée.

Repères dans le code

  • lib/screens/ : parcours et interface utilisateur.
  • lib/repositories/ : règles métier et accès aux données.
  • lib/services/ : connexion MySQL, migrations, cache, journaux et sauvegardes.
  • lib/core/sql_queries.dart : requêtes SQL réutilisées.
  • scripts/Planificator.sql : schéma initial destructif.
  • test/ : tests de repositories, services, modèles et utilitaires.
